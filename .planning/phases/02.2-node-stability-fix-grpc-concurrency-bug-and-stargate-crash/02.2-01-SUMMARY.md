# Phase 02.2 Plan 01: Mutex to RwLock Migration Summary

**One-liner:** Migrated App<T> from `Arc<Mutex<App<T>>>` to `Arc<RwLock<App<T>>>` across grpc.rs, node.rs, and main.rs to enable concurrent gRPC read queries while finalize_block holds an exclusive write lock.

## What Was Built

Replaced the single exclusive Mutex lock on `App<T>` with a reader-writer lock pattern (`tokio::sync::RwLock`) across all three files in the `slay3rd` binary. This allows multiple concurrent gRPC read queries (bank balance, auth info, wasm queries, state sync) to proceed simultaneously while an exclusive write lock is only held during `finalize_block` and `set_block_certificate` calls.

### Read paths (shared `.read().await`):
- `broadcast_tx` handler: `check_tx` reads App state via `ScratchTx` — never commits
- `latest_sequence`: read-only App query
- `current_state`: read-only stream
- `changes_since`: read-only stream
- `handle_cosmos_query`: all Cosmos SDK queries are read-only
- `genesis()`: `app_hash()` is read-only
- `execute_block()` chain_id fetch: read-only `app.info()` call
- `LayerReporter::report()` height fetch: read-only `app.info()` call

### Write paths (exclusive `.write().await`):
- `execute_block()` finalize_block call: mutates App state (DETERMINISM CRITICAL)
- `LayerReporter::report()` set_block_certificate: mutates block record storage

### Unchanged:
- `Mempool` remains `Arc<Mutex<Mempool>>` — single-writer semantics appropriate
- `pending_payloads: Arc<Mutex<BTreeMap<...>>>` — unchanged
- `current_height: Arc<Mutex<u64>>` — unchanged
- `last_digest: Arc<Mutex<[u8; 32]>>` — unchanged
