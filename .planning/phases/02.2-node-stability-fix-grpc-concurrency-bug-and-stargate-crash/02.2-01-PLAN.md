<objective>
Migrate App<T> from `Arc<Mutex<App<T>>>` to `Arc<RwLock<App<T>>>` across the gRPC service, consensus node, and main entry point. This allows concurrent gRPC read queries while finalize_block holds an exclusive write lock, fixing the ~0.1% error rate observed under concurrent gRPC load (issues #178/#162).

Purpose: Eliminate gRPC query starvation during block finalization -- read-only gRPC queries (bank balance, auth info, wasm queries, state sync) should never block behind the expensive finalize_block write path.

Output: All three files (`grpc.rs`, `node.rs`, `main.rs`) use `tokio::sync::RwLock` for `App<T>` access with proper read/write segregation.
</objective>
