# Phase 02.1: Functional Node - Research

**Researched:** 2026-03-20
**Domain:** Rust async P2P networking, tonic gRPC, RocksDB persistence, Cosmos tx pipeline
**Confidence:** HIGH (all major claims verified against source code and official docs)

## Summary

Phase 02.1 closes three architectural gaps left open by Phase 2: the P2P transport is in-process only and cannot span OS processes, the gRPC server is a stub with no real handlers, and the tx pipeline produces empty blocks. The work is primarily wiring — the building blocks (RockStore, cosmos query handlers, BroadcastTx proto stubs, SyncProvider impl) all exist and compile; they just need to be connected.

The most technically demanding piece is the `commonware_p2p::authenticated::lookup` transport swap. The channel registration API is structurally identical to simulated (`network.register(channel_id, quota, backlog)` vs `oracle.control(pk).register(channel_id, quota)`), but peer registration changes from `add_link(src, dst, link)` to `oracle.track(0, BTreeMap<pk, Address>)` where `Address` wraps a `SocketAddr`. The gRPC work is straightforward tonic boilerplate. The tx pipeline requires replacing one stub line in `execute_block()` with a `parse_cosmos_tx()` call on each raw `Bytes` in `payload.txs`. RocksDB is already gated behind a feature flag and `RockStore::open(path)` satisfies the same `PersistentStorage` trait as `MemoryStore` — the call site change in `main.rs` is a type swap plus one directory setup.

**Primary recommendation:** Implement in four sequential tasks: (1) P2P transport swap + testnet scripts, (2) gRPC server with all services, (3) tx pipeline deserialization, (4) RocksDB switch + end-to-end integration test. The P2P and gRPC tasks can proceed in parallel since they touch different regions of main.rs.

## User Constraints (from CONTEXT.md)

### Locked Decisions

#### P2P Transport
- Switch from `commonware_p2p::simulated` to `commonware_p2p::authenticated` — the simulated transport is in-process only and cannot span OS processes; authenticated P2P uses TLS + Ed25519 identity keys and supports real multi-host networking
- Peer discovery: static peer list in TOML config — each node config has `[[peers]]` entries with `address = "host:port"` and `public_key = "ed25519_hex"`. No bootstrap discovery. Matches the static validator set model already established in Phase 2.
- Reuse existing Ed25519 keys as P2P identity — the key material JSON from `tools/generate-testnet-keys` already has `ed25519_private_hex`; authenticated P2P reads identity from the same file. No separate TLS cert files needed.
- Peer address format: `address = "IP:port"` + `public_key = "ed25519_pubkey_hex"` in `[[peers]]` table in node TOML config
- Connection retry: retry with exponential backoff until connected — nodes can start in any order, converge when all are up
- Unit tests: keep existing simulated P2P unit tests (fast, no network), add a new authenticated P2P integration test that spins up real multi-process nodes
- Testnet scripts: update `scripts/testnet.sh` to launch real multi-process nodes with authenticated P2P that actually reach consensus across separate OS processes
- Testnet topology: localhost default (3 processes on one machine, different ports), plus a `docker-compose.yml` showing multi-host configuration

#### gRPC Interface
- Start a real tonic gRPC server listening on `config.grpc_listen` alongside the consensus engine
- Services to expose:
  1. Cosmos SDK query services: bank (balance, all balances), auth (account), wasm (contract state, code info) — using existing handlers in `packages/cosmos/`
  2. `cosmos.tx.v1beta1.Service` — BroadcastTx endpoint for tx submission (sync mode)
  3. `layer.sync.v1` state sync streaming — wire existing `SyncProvider` impl from `packages/app/src/sync.rs`
- Cosmos query handlers wired as-is — do not start the Phase 3 type migration here
- Shared state model: `Arc<Mutex<App<T>>>` shared between gRPC server and consensus engine — consistent with the pattern already established in `LayerNode` and `LayerReporter`
- gRPC server runs concurrently with the consensus engine in the same tokio runtime

#### Transaction Pipeline
- Wire tx format: Cosmos proto tx format (`cosmos.tx.v1beta1`) — the existing infrastructure in `packages/cosmos/tx.rs` parses this format. Phase 3 replaces it entirely.
- BroadcastTx: sync mode only — returns after the tx passes the mempool check (`check_tx`). Block inclusion is asynchronous.
- Full round-trip required: submit tx via gRPC → `check_tx` in mempool → `drain_batch()` at propose time → deserialized `Vec<layer_std::Tx>` passed to `execute_block()` → `finalize_block()` executes CosmWasm msgs → state committed to RocksDB
- Tx deserialization in `execute_block()`: replace the `let txs: Vec<layer_std::Tx> = Vec::new();` stub (node.rs line ~153) with real deserialization from `BlockPayload` raw bytes
- End-to-end success bar: deploy the `contracts/root/` contract (StoreCode + InstantiateContract + ExecuteContract msgs), query resulting state — all via gRPC BroadcastTx with the tx included in a finalized block

#### Storage Persistence
- Switch from `MemoryStore` to `RockStore` (RocksDB) — state persists between restarts
- Single `data_dir` config field: `data_dir = "./data"` in node TOML; app state stored at `{data_dir}/app/`, consensus WAL at `{data_dir}/wal/`
- Remove `wal_path` as a separate top-level config field — subsume into `data_dir`; wal path is `{data_dir}/wal/`
- `layer-storage` `rocksdb` feature flag enabled in `slay3rd/Cargo.toml`

### Pattern 1: commonware_p2p::authenticated::lookup Setup

**What:** Replace simulated network with authenticated lookup transport. The lookup submodule is for peers with known addresses (static config). The signer (private key) provides TLS identity — no separate cert files.

**When to use:** Static validator set where all peer addresses are known at startup.

```rust
// Source: https://docs.rs/commonware-p2p/2026.3.0/commonware_p2p/authenticated/lookup/
use commonware_p2p::authenticated::lookup::{Config, Network};
use commonware_p2p::{Address};
use commonware_utils::ordered::Map;
use std::net::SocketAddr;

// Config uses the Ed25519 private key directly as the TLS signer
let p2p_cfg = Config::local(
    ed25519_private_key.clone(),   // C: Signer — the node's identity key
    b"slay3r-p2p-v1".to_vec(),     // namespace: Vec<u8>
    p2p_listen_addr,               // listen: SocketAddr
    1024 * 1024,                   // max_message_size: u32
);

let (mut network, mut oracle) = Network::new(context.with_label("p2p"), p2p_cfg);

// Register channels BEFORE start()
let (vote_sender, vote_receiver) = network.register(0, quota, 128);
let (cert_sender, cert_receiver) = network.register(1, quota, 128);
let (res_sender, res_receiver) = network.register(2, quota, 128);

// Register peer set: Map<PublicKey, Address>
// Address implements From<SocketAddr> via Symmetric variant
let mut peer_map: Map<ed25519::PublicKey, Address> = Map::new();
for (pk, addr) in all_peers {
    peer_map.insert(pk, addr.into()); // SocketAddr -> Address::Symmetric
}
oracle.track(0, peer_map).await;

// Start AFTER register() calls
let _network_handle = network.start();
```

**Key differences from simulated:**
- `Network::new(context, cfg)` — same signature pattern
- `network.register(channel, quota, backlog)` — different from `oracle.control(pk).register(channel, quota)` in simulated
- `oracle.track(index, Map<pk, Address>)` — replaces both `mgr.track(index, participants)` and `oracle.add_link(...)` calls
- No `Link` struct needed — TLS handles connectivity
- `Config::local()` for localhost testing; `Config::recommended()` for production

### Pattern 2: tonic gRPC Multi-Service Server

**What:** Wire multiple tonic service impls into a single server running as a tokio task.

**When to use:** Whenever multiple gRPC services need to be served from the same port.

```rust
// Source: tonic 0.12.3 official docs
use tonic::transport::Server;

// In run_node(), after app_arc is created:
let grpc_addr: SocketAddr = config.grpc_listen.parse().unwrap();
let app_arc_for_grpc = app_arc.clone();
let chain_id_for_grpc = config.chain_id.clone();

tokio::spawn(async move {
    let svc = LayerGrpcService {
        app: app_arc_for_grpc,
        chain_id: chain_id_for_grpc,
    };

    Server::builder()
        .add_service(
            layer_proto::cosmos::tx::v1beta1::service_server::ServiceServer::new(svc.clone())
        )
        .add_service(
            layer_proto::layer::sync::v1::query_server::QueryServer::new(svc.clone())
        )
        // Cosmos queries go through a single catch-all handler
        .serve(grpc_addr)
        .await
        .expect("gRPC server failed");
});
```

**Note on Cosmos queries:** The existing `parse_cosmos_query()` function in `packages/cosmos/src/query.rs` handles all Cosmos SDK paths. The existing proto stubs don't generate individual tonic service traits for every Cosmos query (those require cosmos-sdk-proto tonic feature). The cleanest approach is to implement a single catch-all gRPC service using a raw `tonic::transport::Server` with a custom tower service, or to use the service stubs from `packages/proto` which already have the `#[cfg(feature = "server")]`-gated tonic traits. For Phase 02.1, implement Cosmos queries as a custom tonic service that handles all `/cosmos.*` paths.

### Pattern 3: Tx Deserialization in execute_block()

**What:** Replace the `Vec::new()` stub with real deserialization from `payload.txs: Vec<Bytes>`.

**When to use:** Any time a block is executed — this is the commit path.

```rust
// In app/slay3rd/src/node.rs execute_block()
// Source: packages/cosmos/src/tx.rs parse_cosmos_tx()

use layer_cosmos::parse_cosmos_tx;

// Replace: let txs: Vec<layer_std::Tx> = Vec::new();
// With:
let chain_id = {
    let app = self.app.lock().await;
    app.info().map(|b| b.chain_id.clone()).unwrap_or_default()
};

let mut txs: Vec<layer_std::Tx> = Vec::new();
for raw_bytes in &payload.txs {
    match parse_cosmos_tx(raw_bytes.clone(), &chain_id) {
        Ok(tx) => txs.push(tx),
        Err(e) => {
            tracing::warn!(error = ?e, "Skipping malformed tx in block");
            // Skip malformed txs rather than rejecting the whole block
            // The proposer's check_tx already validated these; errors here
            // mean the tx was corrupted in transit or the chain_id changed.
        }
    }
}
```

**Critical:** `parse_cosmos_tx` needs the chain_id. `App::info()` returns the last committed block info which includes the chain_id.

### Pattern 4: RocksDB Storage Switch

**What:** Replace `MemoryStore::default()` with `RockStore::open(path)` as the `App<T>` storage backend.

**When to use:** This is the main.rs startup change to enable persistence.

```rust
// Source: packages/storage/src/rocks/mod.rs
// Enable feature: slay3rd/Cargo.toml features = ["rocksdb"]

{
```

**Type parameter change:** `LayerNode<MemoryStore, ed25519::PublicKey>` becomes `LayerNode<RockStore, ed25519::PublicKey>`. Since `LayerNode` is generic over `T: PersistentStorage`, and `LayerReporter` currently hardcodes `App<MemoryStore>`, `LayerReporter` must also become generic: `LayerReporter<T: PersistentStorage>` with `app: Arc<Mutex<App<T>>>`.

### Pattern 5: BroadcastTx Handler (sync mode)

**What:** Accept raw tx bytes, run check_tx, push to mempool, return TxResponse.

**When to use:** gRPC tx submission endpoint.

```rust
// Source: packages/app/src/app.rs check_tx()
// Returns TxResult<PulsarError>

async fn broadcast_tx(
    &self,
    request: tonic::Request<BroadcastTxRequest>,
) -> Result<tonic::Response<BroadcastTxResponse>, tonic::Status> {
    let req = request.into_inner();
    let raw_bytes = bytes::Bytes::from(req.tx_bytes);

    // Parse tx
    let chain_id = {
        let app = self.app.lock().await;
        app.info().map(|b| b.chain_id.clone()).unwrap_or_default()
    };
    let tx = parse_cosmos_tx(raw_bytes.clone(), &chain_id)
        .map_err(|e| tonic::Status::invalid_argument(e.to_string()))?;

    // check_tx: validates sig, sequence, auth
    let check_result = {
        let app = self.app.lock().await;
        app.check_tx(tx)
    };
    if check_result.result.is_err() {
        return Err(tonic::Status::failed_precondition(
            format!("check_tx failed: {:?}", check_result.result.err())
        ));
    }

    // Submit raw bytes to mempool
    let accepted = {
        let mut mempool = self.mempool.lock().await;
        mempool.submit(raw_bytes)
    };
    if !accepted {
        return Err(tonic::Status::resource_exhausted("mempool full"));
    }

    // Return empty success for sync mode
    Ok(tonic::Response::new(BroadcastTxResponse {
        tx_response: Some(cosmos_sdk_proto::cosmos::base::abci::v1beta1::TxResponse {
            code: 0,
            ..Default::default()
        }),
    }))
}
```

### Anti-Patterns to Avoid

- **Using `authenticated::discovery` instead of `authenticated::lookup`:** discovery is for peers with unknown addresses (gossip-based); lookup is for static peer lists. Phase 02.1 uses a static TOML config — use lookup.
- **Calling `network.register()` after `network.start()`:** channels must be registered before `start()` — the `start()` call freezes the channel set.
- **Holding `Arc<Mutex<App<T>>>` locked across await points:** check_tx and finalize_block are sync calls; lock, call, unlock, then do async work. Never hold the lock while awaiting.
- **Using `Config::recommended()` for localhost testnet:** `local()` disables stricter timing checks that would cause unnecessary disconnections on localhost.
- **Hardcoding `App<MemoryStore>` in `LayerReporter`:** When switching to RocksDB, `LayerReporter` must be made generic or use a trait object. The simplest approach is generic: `LayerReporter<T>` with `app: Arc<Mutex<App<T>>>`.
- **Not enabling `rocksdb` feature in `slay3rd/Cargo.toml`:** The `RockStore` type is behind `#[cfg(feature = "rocksdb")]` in `layer-storage/src/lib.rs`. The feature flag must propagate through `slay3rd`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| TLS + Ed25519 auth for P2P | Custom TLS cert management | `commonware_p2p::authenticated::lookup` Config with ed25519 private key | Commonware handles the TLS handshake, mutual auth, and replay prevention natively |
| Tx signature validation | Custom secp256k1 verify | `App::check_tx()` which calls `logic.validate_tx()` | The existing path handles secp256k1, legacy amino JSON, sequence checking, and fee validation |
| Cosmos protobuf encoding/decoding | Custom proto parsing | `parse_cosmos_query()` + `encode_cosmos_response()` + `parse_cosmos_tx()` | All Cosmos SDK proto paths already implemented in `packages/cosmos/` |
| gRPC streaming for state sync | Custom streaming protocol | `layer.sync.v1` QueryServer + `SyncProvider` impl on `App<T>` | The proto service, server stub, and App implementation all exist |
| RocksDB transactions | Manual file-based state | `RockStore::open(path)` + `PersistentStorage` trait | RockStore implements OptimisticTransactionDB with app_hash tracking |
| Connection retry backoff | Manual reconnect loop | `authenticated::lookup` handles reconnection internally | The transport retries connections using configured `dial_frequency` |

**Key insight:** Every major piece of Phase 02.1 infrastructure already exists in the codebase. This phase is integration work, not invention work.

## Common Pitfalls

### Pitfall 1: LayerReporter Type Hardcoding

**What goes wrong:** `LayerReporter` currently has `app: Arc<Mutex<App<MemoryStore>>>` hardcoded (line 110 of main.rs). When `run_node()` switches to `RockStore`, the compiler will reject the reporter construction since types won't match.

**Why it happens:** Phase 2 hardcoded the concrete storage type for simplicity.

**How to avoid:** Make `LayerReporter` generic before switching storage: `struct LayerReporter<T: PersistentStorage + Send + Sync + 'static>` with `app: Arc<Mutex<App<T>>>`. The `impl Reporter for LayerReporter<T>` bound stays the same.

**Warning signs:** Compiler error: `expected App<MemoryStore>, found App<RockStore>` in the reporter construction at main.rs line ~325.

### Pitfall 2: oracle.track() Map Type Mismatch

**What goes wrong:** `oracle.track()` in `authenticated::lookup` requires `Map<pk, Address>` from `commonware_utils::ordered::Map`, NOT a `BTreeMap` or `HashMap`. The Phase 2 simulated code used `Set::try_from(participant_keys.as_slice())` — the Map type for lookup is different.

**Why it happens:** The simulated oracle took `Set<pk>` for participant tracking; the lookup oracle takes `Map<pk, Address>` (key-value: public key → socket address).

**How to avoid:** Build the peer map as:
```rust
use commonware_utils::ordered::Map;
use commonware_p2p::Address;
let mut peers: Map<ed25519::PublicKey, Address> = ...;
// Insert own address too (node registers itself in the peer map)
```

**Warning signs:** Compilation error on `oracle.track(0, ...)` — argument type mismatch.

### Pitfall 3: gRPC Server Blocking the tokio Runtime

**What goes wrong:** `Server::builder().serve(addr).await` is a blocking future — if awaited directly in `run_node()`, it blocks the tokio scheduler before the consensus engine starts.

**Why it happens:** `tonic::transport::Server::serve()` runs until shutdown.

**How to avoid:** Always spawn the gRPC server as a separate tokio task: `tokio::spawn(async move { Server::builder()...serve(grpc_addr).await })`. The consensus engine then starts after in the same task.

**Warning signs:** Node startup appears to hang after "gRPC server starting" log; consensus never begins.

### Pitfall 4: check_tx Panics on Uninitialized App State

**What goes wrong:** `App::check_tx()` calls `self.data.as_ref().unwrap()` (app.rs line 264) — if the app hasn't been initialized from genesis or loaded from storage, this panics.

**Why it happens:** The gRPC server can receive a BroadcastTx request before the consensus engine has executed the first genesis block.

**How to avoid:** Guard check_tx calls:
```rust
let app = self.app.lock().await;
if app.info().is_none() {
    return Err(tonic::Status::unavailable("node not yet initialized"));
}
app.check_tx(tx)
```

**Warning signs:** `called Option::unwrap() on None` panic in check_tx when the first BroadcastTx arrives at startup.

### Pitfall 5: Ed25519 Private Key Loading for P2P

**What goes wrong:** The `commonware_p2p::authenticated::lookup` Config requires an `ed25519::PrivateKey` (implementing the Signer trait), but the existing `KeyMaterial` struct only loads keys as hex strings. The `ed25519_private_hex` field must be decoded to an `ed25519::PrivateKey`.

**Why it happens:** Phase 2 only needed the BLS key material for consensus; the Ed25519 key was loaded as a hex string for reference but never decoded to the native type.

**How to avoid:** Decode the private key at startup:
```rust
use commonware_codec::extensions::DecodeExt;
let ed25519_priv_bytes = hex::decode(&km.ed25519_private_hex)?;
let ed25519_private_key = ed25519::PrivateKey::decode(
    bytes::Bytes::from(ed25519_priv_bytes)
)?;
```

**Warning signs:** Compiler error on `Config::local(km.ed25519_private_hex, ...)` — `String` does not implement `Signer`.

### Pitfall 6: Cosmos Query Handler for gRPC — No Direct Tonic Service Stubs

**What goes wrong:** The existing `packages/cosmos/src/query.rs` handles Cosmos SDK queries using a path-dispatch function (`parse_cosmos_query(path, data, chain_id)`), but there are no generated tonic `Service` trait impls for individual Cosmos gRPC services (bank.Query, auth.Query, etc.) in the workspace.

**Why it happens:** The `cosmos-sdk-proto` crate has tonic support but it's not enabled in the workspace.

**How to avoid:** Implement a single custom tonic service for all Cosmos queries using a raw HTTP/2 path dispatch — or enable tonic on `cosmos-sdk-proto`. The cleanest approach for Phase 02.1: implement a `CosmosQueryService` that implements the `tower::Service` trait and dispatches to `parse_cosmos_query()`. This avoids enabling tonic on the large cosmos-sdk-proto crate.

Alternatively, use `tonic::transport::Server` with a custom `axum` layer or route-based dispatch. Research recommendation: check whether `cosmos-sdk-proto` workspace dependency already has the tonic feature enabled.

**Warning signs:** No `cosmos.bank.v1beta1.query_server::QueryServer` type found — it requires `cosmos-sdk-proto` with `tonic` feature.

### Pitfall 7: SocketAddr Parsing for Peer Addresses from TOML

**What goes wrong:** TOML peer config has `address = "127.0.0.1:7001"` as a string, but `oracle.track()` needs `Address` (wrapping `SocketAddr`). The parsing must happen at startup, and failures should abort the node with a clear error.

**How to avoid:**
```rust
let addr: SocketAddr = peer.address.parse()
    .expect("invalid peer address in config");
let pk: ed25519::PublicKey = ed25519::PublicKey::decode(
    bytes::Bytes::from(hex::decode(&peer.public_key)?)
)?;
peer_map.insert(pk, Address::from(addr)); // From<SocketAddr> for Address
```

```rust
// In app/slay3rd/src/grpc.rs
use layer_proto::cosmos::tx::v1beta1::{
    service_server::Service as CosmTxService,
    BroadcastTxRequest, BroadcastTxResponse,
};
use layer_cosmos::parse_cosmos_tx;

#[derive(Clone)]
pub struct LayerGrpcService<T: PersistentStorage + Send + Sync + 'static> {
    pub app: Arc<Mutex<App<T>>>,
    pub mempool: Arc<Mutex<Mempool>>,
    pub chain_id: String,
}

#[tonic::async_trait]
impl<T: PersistentStorage + Send + Sync + 'static> CosmTxService for LayerGrpcService<T> {
    async fn broadcast_tx(
        &self,
        request: tonic::Request<BroadcastTxRequest>,
    ) -> Result<tonic::Response<BroadcastTxResponse>, tonic::Status> {
        let raw_bytes = bytes::Bytes::from(request.into_inner().tx_bytes);
        let tx = parse_cosmos_tx(raw_bytes.clone(), &self.chain_id)
            .map_err(|e| tonic::Status::invalid_argument(e.to_string()))?;
        let check = {
            let app = self.app.lock().await;
            if app.info().is_none() {
                return Err(tonic::Status::unavailable("node initializing"));
            }
            app.check_tx(tx)
        };
        if check.result.is_err() {
            return Err(tonic::Status::failed_precondition(
                format!("{:?}", check.result.err())
            ));
        }
        let accepted = { self.mempool.lock().await.submit(raw_bytes) };
        if !accepted {
            return Err(tonic::Status::resource_exhausted("mempool full"));
        }
        Ok(tonic::Response::new(BroadcastTxResponse {
            tx_response: Some(Default::default()),
        }))
    }
    // ... other required methods (get_tx, txs_event, simulate) -> unimplemented
}
```

## Open Questions

1. **Cosmos query tonic service stubs**
   - What we know: `packages/cosmos/src/query.rs` has `parse_cosmos_query(path, data, chain_id)` which handles all Cosmos SDK paths. The `cosmos-sdk-proto` crate has tonic feature support.
   - What's unclear: Whether the cosmos-sdk-proto tonic services are already enabled in the workspace (not visible in the files read). If not, a custom catch-all handler is needed.
   - Recommendation: At plan time, check `packages/cosmos/Cargo.toml` for `cosmos-sdk-proto` tonic features. If not enabled, implement a custom `tower::Service` dispatching to `parse_cosmos_query()`. The planner should add a task to verify this.

2. **`Config::local()` vs `Config::recommended()` signature**
   - What we know: `Config::local()` takes 4 params (signer, namespace, listen_addr, max_message_size) and is appropriate for localhost testing. `Config::recommended()` likely adds more security parameters.
   - What's unclear: The exact field-by-field Config struct has many fields (synchrony_bound, handshake timeouts, etc.) — `local()` may not set all of them in a way that works across processes on the same machine.
   - Recommendation: Start with `Config::local()` for the testnet, monitor for handshake failures, and switch specific fields toward `Config::recommended()` values if needed.

3. **`commons_utils::ordered::Map` vs `BTreeMap` for peer_map**
   - What we know: `oracle.track()` requires `Map<pk, Address>` from `commonware_utils::ordered::Map`.
   - What's unclear: Whether `Map` has a simple `new()` + `insert()` API or requires a specific constructor.
   - Recommendation: Verify by checking `commonware_utils` docs or source. The example code shows `[(...), (...)].try_into().unwrap()` for small static maps; for dynamic iteration use whatever Map's builder pattern is.
