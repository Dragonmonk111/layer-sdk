# Phase 2.1 Plan 04: Cosmos Query Dispatch + tx-sender Summary

**One-liner:** Tower Service axum fallback dispatches /cosmos.bank.*, /cosmos.auth.*, /cosmwasm.wasm.* gRPC paths to handle_cosmos_query(); new tx-sender CLI signs and submits MsgStoreCode/MsgInstantiateContract/MsgExecuteContract via BroadcastTx using deterministic deployer key

## What Was Built

### Task 1: Cosmos Query Dispatch (commit 8180415)

Replaced the dead stub `let _ = (cosmos_app, cosmos_chain_id)` in `main.rs` with a working Cosmos SDK gRPC query dispatch path. The approach uses `tonic::service::Routes::from(axum::Router)` to add an axum fallback router beneath the tonic services.

**`app/slay3rd/src/grpc.rs` additions:**
- `CosmosQueryState<T>` struct with manual `Clone` impl (wraps `Arc<Mutex<App<T>>>` + `chain_id`)
- `CosmosQueryService<T>` struct implementing `tower_service::Service<http::Request<AxumBody>>`
- `CosmosQueryFuture` type alias resolving the `Self::Future` ambiguity from multiple Service trait impls in scope
- `handle_cosmos_request()` async fn: 5-byte gRPC frame prefix stripping, `handle_cosmos_query()` dispatch, gRPC response framing with `grpc-status` trailer header
- `cosmos_query_router()` returning `axum::Router::new().fallback_service(CosmosQueryService { state })`

**`app/slay3rd/src/main.rs` changes:**
- gRPC server spawn block rewritten: `cosmos_query_router(cosmos_state)` -> `tonic::service::Routes::from(cosmos_router)` -> `GrpcServer::builder().add_routes(cosmos_routes).add_service(...)`
- `default_genesis()` updated to include a funded deployer account derived from `SHA256("slay3r-testnet-deployer-v1")[0..32]` (1,000,000,000,000 upulsar)
- Both `#[cfg(feature = "rocksdb")]` and `#[cfg(not(feature = "rocksdb"))]` branches handled for `CosmosQueryState` type

### Task 2: tools/tx-sender Binary (commit b0daa79)

Created a new Rust CLI binary at `tools/tx-sender/` that:
- Derives the deployer secp256k1 key deterministically from `SHA256("slay3r-testnet-deployer-v1")` (same derivation as `default_genesis()`)
- Queries account sequence via `tonic::client::Grpc::unary()` + `ProstCodec<QueryAccountRequest, QueryAccountResponse>`
- Builds, signs, and submits `MsgStoreCode`, `MsgInstantiateContract`, `MsgExecuteContract` via `TxServiceClient::broadcast_tx()`
- Queries contract state via raw gRPC to `/cosmwasm.wasm.v1.Query/SmartContractState`
- Queries bank balance via raw gRPC to `/cosmos.bank.v1beta1.Query/AllBalances`

All proto types sourced from `layer-proto` (prost 0.13, tonic 0.12 compatible). Manual proto bytes encoding via `.encode_to_vec()` wrapped in `cosmrs::Any { type_url, value }`.

**Updated `scripts/testnet.sh` `cmd_e2e()`:**
- Step 3: Build tx-sender unconditionally (error if build fails — no PARTIAL fallback)
- Step 4: Query deployer balance
- Steps 5-6: StoreCode (--wasm) -> InstantiateContract (--code-id, auto gov_address msg)
- Steps 7-8: ExecuteContract + query (when contract_address is available)
- Removed all conditional `if [[ -f "$tx_sender_bin" ]]; then ... else PARTIAL ... fi` branches

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] axum Handler trait version conflict**
- **Found during:** Task 1
- **Issue:** `cosmos_query_fallback` defined as axum async fn + `AxumState<T>` extractor. The `.fallback()` call in main.rs compares axum 0.7's Handler (tonic's transitive dep) vs axum 0.8 types (commonware-runtime transitive dep). E0277: `impl Handler<...>` not satisfied.
- **Fix:** Redesigned to use `tower_service::Service` directly. `CosmosQueryService<T>` implements the tower Service trait manually. Used `axum::Router::new().fallback_service(svc)` which bypasses the Handler trait check entirely.
- **Files modified:** app/slay3rd/src/grpc.rs, app/slay3rd/Cargo.toml (+tower-service="0.3")
- **Commit:** 8180415

**2. [Rule 1 - Bug] Self::Future ambiguity from multiple Service impls**
- **Found during:** Task 1 (while implementing tower Service)
- **Issue:** Multiple Service traits in scope (tower, tonic, commonware) all define `type Future`; `type Future = impl Future<...>` produces E0223 ambiguity.
- **Fix:** Added explicit `CosmosQueryFuture` type alias: `type CosmosQueryFuture = Pin<Box<dyn Future<Output = Result<http::Response<AxumBody>, Infallible>> + Send>>`; used it in the impl.
- **Files modified:** app/slay3rd/src/grpc.rs
- **Commit:** 8180415

**3. [Rule 2 - Missing Critical] Manual Clone for CosmosQueryState/CosmosQueryService**
- **Found during:** Task 1
- **Issue:** `#[derive(Clone)]` requires `T: Clone` but `RockStore` doesn't implement `Clone`. axum's `fallback_service` requires the service to be `Clone`.
- **Fix:** Wrote manual `Clone` impls that clone only the `Arc` pointer (not `T`), so `RockStore`'s missing `Clone` impl is not required.
- **Files modified:** app/slay3rd/src/grpc.rs
- **Commit:** 8180415

**4. [Rule 3 - Blocker] clap proc-macro2 version conflict**
- **Found during:** Task 2
- **Issue:** clap 4.5+ requires proc-macro2 >=1.0.106; workspace has 1.0.86 (locked by criterion via commonware-runtime). No clap version 4.3-4.5 range satisfies all constraints.
- **Fix:** Replaced clap with manual `std::env::args()` parsing. No behavior change; all subcommands and flags preserved.
- **Files modified:** tools/tx-sender/Cargo.toml (removed clap dep), tools/tx-sender/src/main.rs (parse_args fn)
- **Commit:** b0daa79

**5. [Rule 3 - Blocker] cosmos-sdk-proto prost 0.11 incompatible with tonic 0.12 ProstCodec**
- **Found during:** Task 2
- **Issue:** `cosmos-sdk-proto` 0.18 uses `prost = "^0.11"`. `tonic::codec::ProstCodec` requires `prost::Message` from prost 0.13. `ServiceClient` from cosmos-sdk-proto also uses an incompatible tonic version.
- **Fix:** Switched all proto types to `layer-proto` (workspace package compiled with prost 0.13 + tonic 0.12). Removed `cosmos-sdk-proto` from tx-sender Cargo.toml entirely.
- **Files modified:** tools/tx-sender/Cargo.toml, tools/tx-sender/src/main.rs
- **Commit:** b0daa79

**6. [Rule 1 - Bug] QueryAllBalancesRequest has no `resolve_denom` field in layer-proto**
- **Found during:** Task 2 (initial draft used cosmos-sdk-proto 0.21 API)
- **Issue:** `resolve_denom` field only exists in cosmos-sdk-proto >=0.21; layer-proto's bank proto has only `address` + `pagination`.
- **Fix:** Removed the `resolve_denom` field from the struct initialization.
- **Files modified:** tools/tx-sender/src/main.rs
- **Commit:** b0daa79

**7. [Rule 1 - Bug] MsgStoreCode has no `instantiate_permission` field in layer-proto**
- **Found during:** Task 2
- **Issue:** `instantiate_permission` field is absent from layer-proto's cosmwasm.wasm.v1.MsgStoreCode (only `sender` + `wasm_byte_code`).
- **Fix:** Removed the field from MsgStoreCode construction.
- **Files modified:** tools/tx-sender/src/main.rs
- **Commit:** b0daa79

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| tower Service + fallback_service | Only way to avoid the axum 0.7 vs 0.8 Handler trait check without patching tonic or commonware deps |
| layer-proto over cosmos-sdk-proto | prost 0.13 compatibility with tonic 0.12 ProstCodec; cosmos-sdk-proto 0.18 is a prost 0.11 island |
| Manual CLI parsing | proc-macro2 workspace lock (1.0.86) cannot satisfy clap 4.5+ requirement (1.0.106); forced by commonware-runtime → criterion → clap dependency chain |
| Manual Clone on CosmosQueryState | RockStore has no Clone impl; only Arc<> pointer needs cloning for the fallback_service router |
