## Decisions Made

- **lookup Oracle as Blocker:** The lookup module's Oracle implements `commonware_p2p::Blocker` directly. The simplex config uses `oracle` directly (not `oracle.control(pk)` as in simulated P2P).
- **Config::local() namespace:** Takes `&[u8]` reference, not `Vec<u8>` (verified from source). Passed as `b"slay3r-p2p-v1"`.
- **Map construction:** `Map::try_from(sorted_slice)` built from a sorted `Vec<(PublicKey, Address)>`. The research doc showed try_into() from array — adapted for dynamic Vec by sorting first.
- **Manual Clone for generics:** Both `LayerReporter<T>` and `LayerGrpcService<T>` needed Clone for tonic/consensus traits. Since `T: PersistentStorage` doesn't imply `T: Clone` and `RockStore` doesn't impl Clone, manual implementations that clone the `Arc` fields were needed.
- **Cosmos query deferred:** Full HTTP/2-level cosmos query interception (for /cosmos.* paths) requires a tower layer or axum router integration. These deps are transitive but not direct deps. Plan 03 adds this. Plan 02 wires the import and function reference.
- **Test deserialization, not finalize:** test_execute_block_with_real_txs tests the parse_cosmos_tx() call path directly. finalize_block may reject txs whose signer isn't in genesis — test accepts that.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] LayerGrpcService Clone requires T: Clone — broke with RockStore**
- **Found during:** Task 1 (compilation of main.rs with rocksdb feature)
- **Issue:** `#[derive(Clone)]` on `LayerGrpcService<T>` generates a `Clone` bound on T. RockStore doesn't implement Clone, so `grpc_svc.clone()` failed.
- **Fix:** Replaced `#[derive(Clone)]` with a manual `impl<T> Clone for LayerGrpcService<T>` that clones the Arc fields, requiring no T: Clone.
- **Files modified:** `app/slay3rd/src/grpc.rs`
- **Verification:** `cargo check -p slay3rd --features rocksdb` passes
- **Committed in:** 0f3abfc (Task 1 commit)

**2. [Rule 1 - Bug] LayerReporter Clone requires T: Clone — same issue as LayerGrpcService**
- **Found during:** Task 1 (compilation)
- **Issue:** `#[derive(Clone)]` on `LayerReporter<T>` which needs Clone for the Reporter trait. Same RockStore: Clone issue.
- **Fix:** Removed `#[derive(Clone)]`, added manual Clone impl.
- **Files modified:** `app/slay3rd/src/main.rs`
- **Verification:** `cargo check -p slay3rd --features rocksdb` passes
- **Committed in:** 0f3abfc (Task 1 commit)

**3. [Rule 4 - Scope Boundary] Cosmos query HTTP/2 tower layer deferred to Plan 03**
- **Found during:** Task 1 (attempting to implement tower service wrapping for cosmos query routing)
- **Issue:** Tower service wrapping requires `tower` and `axum` as direct dependencies (not just transitive). Adding them to slay3rd would work but is an architectural extension. The acceptance criteria only requires handle_cosmos_query to be "wired."
- **Action taken:** Wired handle_cosmos_query import and function reference in main.rs. Plan 03 will add the full HTTP/2 router.
- **Impact:** The gRPC server starts and serves BroadcastTx + state sync. Cosmos SDK queries (/cosmos.bank.*, etc.) will return gRPC UNIMPLEMENTED until Plan 03 adds the router. This is acceptable for Plan 02.
