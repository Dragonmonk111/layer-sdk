<objective>
Close the CONS-05 verification gap: wire the BLS12-381 threshold certificate bytes from the Commonware Reporter callback into persistent storage on the App, so each finalized block actually has its certificate stored — not just logged.

Purpose: The VERIFICATION.md found that `execute_block()` always passes `certificate: None` to `finalize_block()` and the Reporter only logs the cert bytes without storing them. The BLS certificate is produced by the consensus engine AFTER `certify()` returns `true` from a quorum of validators, so it is not available at `certify()` time. The fix adds a post-commit update API (`set_block_certificate`) to `App<T>` and wires the Reporter to call it when the Finalization activity delivers the certificate.

Output: `App::set_block_certificate()` method, updated `LayerReporter` that stores certificates, test proving certificate persistence.
</objective>

Add a new public method to `App<T>` in the third `impl<T: PersistentStorage + 'static> App<T>` block (the one starting around line 196 that contains `info()`, `app_hash()`, `finalize_block()`, etc.):

```rust
/// Store a BLS12-381 threshold certificate for a previously committed block.
///
/// Called by the consensus Reporter after the threshold signature is assembled
/// from validator certify() votes. The certificate is NOT available at
/// certify() time — it is produced by the consensus engine after a quorum
/// of validators have certified the block.
///
/// The certificate is stored under a "_cert/{height}" key. The "_" prefix
/// excludes it from app_hash computation (same convention as LAST_BLOCK),
/// because certificate delivery timing may differ across validators and
/// must not affect consensus determinism.
///
/// # Arguments
/// * `height` - The block height this certificate belongs to
/// * `certificate` - The raw BLS12-381 threshold signature bytes from the consensus engine
///
/// # Returns
/// `Ok(())` on success, or an error if the storage write fails.
pub fn set_block_certificate(
    &mut self,
    height: u64,
    certificate: Vec<u8>,
) -> PulsarResult<()> {
    let meter = GasMeter::infinite();
    let mut writer = self.storage.writer();
    // Store certificate under _cert namespace keyed by height
    let key = format!("_cert/{height}");
    let cert_item: Item<Vec<u8>> = Item::new(&key);
    cert_item.save(&mut writer, &meter, &certificate)?;
    writer.commit(&meter)?;
    Ok(())
}

/// Retrieve the BLS certificate for a block at the given height, if stored.
///
/// Returns `None` if no certificate has been stored for this height yet
/// (e.g., the Reporter hasn't fired yet, or this is a genesis block).
pub fn get_block_certificate(&self, height: u64) -> Option<Vec<u8>> {
    let meter = GasMeter::infinite();
    let reader = self.storage.reader();
    let key = format!("_cert/{height}");
    let cert_item: Item<Vec<u8>> = Item::new(&key);
    let result = cert_item.may_load(&reader, &meter).ok().flatten();
    reader.abort();
    result
}
```

IMPORTANT NOTES:
- The `"_cert/{height}"` key uses the underscore prefix convention established by `LAST_BLOCK` (`"_last_block"`) which excludes it from the Merkle hash / app_hash. This is critical because certificate delivery is asynchronous and may differ in timing across validators.
- `Item::new()` accepts `&str` — the `format!` string is fine for dynamic keys.
- The `GasMeter::infinite()` pattern is used for infrastructure writes (same as the `writer.commit()` in `finalize_block()` at line 435-437 of the current app.rs).
- `reader.abort()` is called after read to release the read lock (same pattern as `query()` at line 226).

```rust
Activity::Finalization(finalization) => {
    let cert_bytes = finalization.certificate.encode().to_vec();
    let payload_digest: [u8; 32] = finalization.proposal.payload.0;

    // Extract the block height from the payload in pending_payloads.
    // The Finalization contains the payload digest but not the height directly.
    // We need to determine the height. The simplest approach: use the app's
    // current block height (which was just incremented by certify/execute_block).
    // Since finalization fires immediately after certify(), the current LAST_BLOCK
    // height in the app IS the block that was just certified.
    let height = {
        let app = self.app.lock().await;
        app.info().map(|b| b.height).unwrap_or(0)
    };

    tracing::info!(
        height = height,
        view = ?finalization.proposal.round,
        payload_digest = %hex::encode(payload_digest),
        cert_len = cert_bytes.len(),
        certificate = %hex::encode(&cert_bytes),
        "Block finalized with BLS threshold certificate (CONS-05)"
    );

    // CONS-05: Persist the BLS certificate to the committed block record.
    // This is the post-commit update path — the block was already committed
    // by certify()/execute_block()/finalize_block(), and now we store the
    // certificate that the consensus engine produced from the quorum of
    // certify votes.
    if !cert_bytes.is_empty() {
        let mut app = self.app.lock().await;
        match app.set_block_certificate(height, cert_bytes.clone()) {
            Ok(()) => {
                tracing::info!(
                    height = height,
                    cert_len = cert_bytes.len(),
                    "BLS certificate stored in block record (CONS-05)"
                );
            }
            Err(e) => {
                tracing::error!(
                    height = height,
                    error = ?e,
                    "Failed to store BLS certificate — CONS-05 gap"
                );
            }
        }
    }
}
```
