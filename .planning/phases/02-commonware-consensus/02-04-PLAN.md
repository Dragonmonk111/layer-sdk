**Part A: Testnet Orchestration Script**

Create `scripts/testnet.sh` — a bash script that:

1. Builds the slay3rd binary: `cargo build -p slay3rd --release`
2. Generates testnet key material: `cargo run --manifest-path tools/generate-testnet-keys/Cargo.toml -- --output-dir /tmp/layer-testnet --validators 3`
3. Creates 3 node config TOML files at `/tmp/layer-testnet/node-{0,1,2}/config.toml`:
   - Node 0: P2P on 127.0.0.1:26656, gRPC on 127.0.0.1:9090
   - Node 1: P2P on 127.0.0.1:26657, gRPC on 127.0.0.1:9091
   - Node 2: P2P on 127.0.0.1:26658, gRPC on 127.0.0.1:9092
   - Each config points to its own key file, WAL directory, and RocksDB path
   - Each config lists the other two nodes as peers
4. Creates a genesis.json file with a test validator set and initial balances
5. Starts 3 slay3rd processes in the background, capturing logs to `/tmp/layer-testnet/node-{0,1,2}/node.log`
6. Prints PID of each process
7. Waits for a configurable number of blocks (default 20) by tailing logs
8. Provides a `stop` command: `scripts/testnet.sh stop` kills all 3 processes

**Part B: Consensus Verification Script**

Create `scripts/verify-consensus.sh` — validates CONS-02, CONS-03, CONS-04:

1. **AppHash comparison** (CONS-02, CONS-04):
   - Extract AppHash values at block heights 5, 10, 15 from each node's log
   - Compare across all 3 nodes — all must match
   - Exit 1 with clear error message if any mismatch

2. **Crash recovery test** (CONS-03):
   - Kill node 2 (SIGKILL — simulate crash, not graceful shutdown)
   - Wait for nodes 0 and 1 to produce 10 more blocks (2/3 majority can continue)
   - Restart node 2 from its existing WAL and data directory
   - Wait for node 2 to catch up (check its log for block height matching nodes 0/1)
   - Compare AppHash of the catch-up block across all 3 nodes
   - Exit 1 if node 2 fails to catch up or AppHash diverges

3. **Certificate extraction** (CONS-05):
   - Extract a BLS certificate from a finalized block (from node 0's log or a gRPC query)
   - Write the certificate bytes to a file for the verify-cert tool
   - Output the certificate hex for human inspection

**Part C: Offline Certificate Verifier**

Create `tools/verify-cert/` as a standalone binary (like generate-testnet-keys):

`tools/verify-cert/Cargo.toml`:
```toml

[dependencies]
commonware-cryptography = "2026.3.0"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
hex = "0.4"
```

`tools/verify-cert/src/main.rs`:
This tool takes:
- A certificate file (JSON or binary — format depends on what threshold_simplex produces)
- The shared threshold public key (from the keygen output)
- The block digest that was signed

It verifies the BLS12-381 threshold signature and prints:
- `VALID: Certificate for block <digest_hex> verified with threshold public key <pk_hex>`
- Or `INVALID: Certificate verification failed: <reason>`

Usage: `cargo run --manifest-path tools/verify-cert/Cargo.toml -- --cert <path> --pubkey <hex> --digest <hex>`

The exact verification API depends on `commonware-cryptography::bls12381`. The executor MUST inspect `cargo doc` to find the correct signature verification function (likely `verify()` on a threshold public key type).
