**Part B: Relay Implementation with Shared pending_payloads**

Create `app/slay3rd/src/relay.rs` implementing the Commonware `Relay` trait for broadcasting block payloads between validators.

```rust
//! LayerRelay: broadcasts block payloads to peer validators via commonware-p2p.
//!
//! CRITICAL DESIGN: LayerRelay holds the SAME `Arc<Mutex<BTreeMap<[u8; 32], BlockPayload>>>`
//! as LayerNode::pending_payloads. When the relay receives a broadcast payload from
//! another validator, it deserializes the BlockPayload and inserts it into the shared
//! pending_payloads map. This ensures non-proposer validators can look up the payload
//! during verify() — without this wiring, only the proposer would have the payload
//! in pending_payloads, and 2-of-3 validators would always fail verify().
```

The Relay trait requires:
- `type Digest` -- `[u8; 32]`
- `type PublicKey` -- the BLS or Ed25519 public key type from the scheme
- `type Plan` -- broadcast plan (which peers to send to)
- `fn broadcast(&mut self, payload: Self::Digest, plan: Self::Plan) -> impl Future<Output = ()> + Send`

The `LayerRelay` struct MUST contain:
```rust
pub struct LayerRelay {
    /// SHARED with LayerNode::pending_payloads — same Arc instance.
    /// When payloads arrive from other validators, they are inserted here
    /// so that verify() can find them.
    pending_payloads: Arc<Mutex<BTreeMap<[u8; 32], BlockPayload>>>,

    /// Local payload store: digest -> serialized BlockPayload bytes
    /// Used for serving payloads to peers who request them.
    payload_store: Arc<Mutex<BTreeMap<[u8; 32], Vec<u8>>>>,

    // ... P2P sender handle ...
}

impl LayerRelay {
    /// Create a new relay that shares pending_payloads with a LayerNode.
    ///
    /// IMPORTANT: `pending_payloads` MUST be the same Arc returned by
    /// `LayerNode::pending_payloads()`. This is how non-proposers receive
    /// payloads for verify().
    pub fn new(
        pending_payloads: Arc<Mutex<BTreeMap<[u8; 32], BlockPayload>>>,
        // ... other params ...
    ) -> Self { ... }
}
```

The broadcast implementation should:
1. Serialize the BlockPayload to bytes and store in `payload_store`
2. Also deserialize and insert into `pending_payloads` (so local verify works)
3. Use `commonware-p2p` to send the serialized bytes to all peers specified in the plan
4. On receiving a payload from a peer: deserialize the BlockPayload, compute its digest, insert into `pending_payloads`

IMPORTANT: The exact `Relay` trait API must be confirmed by inspecting `cargo doc -p commonware-consensus`. The research confirmed the trait signature but the `Plan` type may be more specific in `threshold_simplex`. The executor MUST adapt the implementation to match the actual API.

If the P2P layer is too complex for Phase 2: implement a simplified `LayerRelay` that shares payloads through in-process channels (suitable for the 3-node testnet running on localhost). The CRITICAL requirement is that the relay populates the shared `pending_payloads` map. Add a TODO for production-grade P2P relay.
