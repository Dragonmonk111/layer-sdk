<objective>
Wire the complete consensus runtime: BLS DKG key generation tooling, node configuration, P2P relay for payload broadcast, and the slay3rd main.rs that spawns the Commonware consensus engine alongside gRPC services.

Purpose: After Plan 02, LayerNode implements the consensus bridge but has no networking, no key material, and no runtime. This plan provides: (1) an offline DKG keygen tool that generates BLS key shares for a 3-node testnet, (2) a config system that loads these keys and peer addresses, (3) a Relay implementation for broadcasting block payloads between validators, and (4) the main.rs that ties everything together — spawning the Commonware `threshold_simplex` engine on a `tokio::Runner` alongside the existing gRPC server. After this plan, `slay3rd` is a runnable consensus node.

Output: Offline keygen utility, node config, relay implementation, fully wired main.rs, compilable slay3rd binary ready for multi-node testing.

**Part A: Relay Implementation**

Create `app/slay3rd/src/relay.rs` implementing the Commonware `Relay` trait for broadcasting block payloads between validators.

```rust
//! LayerRelay: broadcasts block payloads to peer validators via commonware-p2p.
//!
//! In Phase 2, this implementation stores payloads locally and broadcasts
//! their digests to peers. Peers fetch the full payload on demand.
```

The Relay trait requires:
- `type Digest` — `[u8; 32]`
- `type PublicKey` — the BLS or Ed25519 public key type from the scheme
- `type Plan` — broadcast plan (which peers to send to)
- `fn broadcast(&mut self, payload: Self::Digest, plan: Self::Plan) -> impl Future<Output = ()> + Send`

The implementation should:
1. Store the payload in a shared `Arc<Mutex<BTreeMap<[u8; 32], Vec<u8>>>>` (digest -> serialized BlockPayload bytes)
2. Use `commonware-p2p` to send the digest to all peers specified in the plan
3. Provide a `get_payload(&self, digest: &[u8; 32]) -> Option<Vec<u8>>` method for peers to fetch payloads

IMPORTANT: The exact `Relay` trait API must be confirmed by inspecting `cargo doc -p commonware-consensus`. The research confirmed the trait signature but the `Plan` type may be more specific in `threshold_simplex`. The executor MUST adapt the implementation to match the actual API.

If the P2P layer is too complex for Phase 2: implement a simplified `LayerRelay` that shares payloads through in-process channels (suitable for the 3-node testnet running on localhost). Add a TODO for production-grade P2P relay.

Update `app/slay3rd/src/lib.rs` to add `pub mod relay;`.

**Part B: main.rs — Full Consensus Runtime**

Rewrite `app/slay3rd/src/main.rs` to be a complete consensus node entry point.

The main function should:

1. **Parse config**: Load `NodeConfig` from TOML file (path from CLI arg or env var `SLAY_CONFIG`)
2. **Init tracing**: Set up tracing-subscriber with env-filter
3. **Init storage**: Create `MemoryStore` (default) or `RockStore` (if rocksdb_path set)
4. **Init app**: Create `App::new(storage, StateMachine::new(&config))`, then either `load_from_storage()` or `init()` from genesis
5. **Init mempool**: Create `Mempool::new(config.mempool_max_pending)`
6. **Create LayerNode**: `LayerNode::new(Arc::new(Mutex::new(app)), Arc::new(Mutex::new(mempool)), initial_height)`
7. **Load BLS keys**: Read the key material from `config.bls_key_path`
8. **Create Relay**: `LayerRelay::new(...)` with P2P configuration
9. **Create Reporter**: A simple logging reporter (logs consensus activity via tracing)
10. **Build consensus Config**: Wire all components into the `threshold_simplex::Config` (or `simplex::Config` with BLS scheme):
    - `scheme`: BLS12-381 threshold signing scheme with loaded key material
    - `elector`: Default round-robin elector from commonware-consensus
    - `blocker`: Default blocker from commonware-p2p (or a no-op for Phase 2 localhost)
    - `automaton`: The LayerNode instance
    - `relay`: The LayerRelay instance
    - `reporter`: The logging reporter
    - `partition`: "slay3r"
    - `leader_timeout`: Duration from config
    - `certification_timeout`: Duration from config
    - Other fields with reasonable defaults
11. **Spawn consensus**: Use `commonware_runtime::tokio::Runner` to spawn the consensus engine
12. **Spawn gRPC**: Start the gRPC server alongside consensus, using `LayerNode::app()` for query handling
